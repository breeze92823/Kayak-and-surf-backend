# Kayak & Surf — BACKEND (game server)

Workspace map: ../CLAUDE.md. Frontend (3D client) lives at `../Kayak-and-surf`. Colyseus + Mongo, ported from `C:\ThreeJS\Kick-per-click\Kick-per-click-backend`.

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`, client calls `joinOrCreate("world", { userId, username, avatar, pfp })`). Client-authoritative: the server only bounds/sanitises (`src/sanitize.ts`) and relays. `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable; guests (`guest-` ids) are never saved. `/health` for Legion; `/monitor` and the playground are dev-only.
- Messages client -> server: `pose` (x,y,z,yaw, pitch/roll (slide tilt, clamped to ±π/2), speed01, grounded, pose (client: '' / 'surf' / 'climb'), boat (equipped Kayak Shop id, `ID_PATTERN`; "" = the log raft); every client draws everyone else from these roster fields, client `src/remotePlayers.js`), `setAvatar`, `setPfp`, `climbBest {distance}`, `saveProgress`, `identify` (both join options and `identify` carry `username` = display name and `handle` = @username). Server -> client: `progress` / `noProgress` / `serverError` (private; `progress`/`noProgress` carry `petsRev: 0`), `leaderboard` (broadcast: `coins`, `trophies`, `playtime` boards, up to `LEADERBOARD_ROWS` `{ id, name, value }` rows each, `id` = the sessionId for an online player; the client paints its hub boards COIN / WINS (= trophies) / PLAYTIME from it and saves `playtime` in `saveProgress`). Roster (`PlayerState`): also `handle`, `signedIn` (has a Bloxity id) and `trading` (in a trade: the client's Trade list shows Busy).
- Pet trades (`src/rooms/trades.ts` `Trades`, the one server-authoritative part; tests `test/Trades.test.ts`). WorldRoom keeps each session's pet list (`pets`, from the loaded doc, then every `saveProgress`) and a `petsRev` per session (0 on each load, +1 per finished trade); a `saveProgress` whose `petsRev` differs is stale (written before a trade landed) and its `pets`/`petTeam` are dropped. Guests can't trade. Client -> server: `tradeRequest {to}`, `tradeRespond {from, ok}`, `tradeOffer {uids}` (the whole offer; unowned uids and repeats dropped, at most `TRADE.maxPets` 9), `tradeAccept {ok}`, `tradeCancel`. Server -> client: `tradeIncoming {from, name}`, `tradeIncomingGone {from}`, `tradeRequestEnded {to, reason}` (declined/expired/busy/unavailable/guest/cooldown), `tradeOpen {partner, name}`, `tradeUpdate {mine, theirs (pets), accepted {me, them}, countdown (ms left), note? (empty/fullMe/fullThem)}`, `tradeClosed {reason (cancelled/left), byMe}`, `tradeDone {gave (uids), got (pets, clashing uids renumbered), petsRev}`. Requests expire after `TRADE.requestMs` (15 s), one every `requestCooldownMs`; any offer change clears both Accepts; both accepted -> `countdownMs` (3 s) -> re-check ownership and `TRADE.storage` (50 = client `PET_TEAM.storage`, only for the side that gains pets) -> swap, both lists saved at once (`commitPets`). Leaving, reconnecting or changing identity ends the trade. Tests share one booted server (`test/server.ts`).
- Daily rewards (`src/daily.ts`, after Paper-plane-backend's; tests `test/Daily.test.ts`), server-authoritative for signed-in players (client `src/daily.js`; guests keep theirs in localStorage). A 7-day week per account, saved as `daily {start, claimed[]}` on the doc (never written by `saveProgress`): Day N opens `(N-1) * DAILY_DAY_MS` after `start` (env `DAILY_DAY_MS` shortens days for testing; default 24 h), claimable in any order; claiming the last starts the next week at max(start + 7 days, now). `loadProgress` -> `loadDaily` sends `daily` = `dailyView` `{start, claimed, now, dayMs}` (null for a guest); a doc without `daily` (or a new account, upserted with `tutorialStep: 0` so it isn't read as a legacy save) gets its week saved at once; with no database the week lasts the connection. Client -> server `claimDaily {day}`; server -> client `dailyClaimed {day, reward, daily}` (recorded in memory before the save is awaited, so a double click can't claim twice) or `dailyDenied {day, reason: day|claimed|locked|signin, daily?}`. `DAILY_REWARDS` (coins/trophies/spins `amount`, boost `boost`/`pct`/`time`, pet `pet`) must match the client's config `DAILY_REWARDS.days`. Identity changes drop the session's week until the new one loads.
- Saved progress shape (`PlayerDoc`): `coins`, `trophies`, `bestDistance`, `playtime`, `tutorialStep` (only ever moves forward; `TUTORIAL_DONE_STEP`), `coaches[]`, `equippedCoaches[]` (<= `COACH_SLOTS` 3, must be owned), `kayaks[]` (owned Kayak Shop boat ids, <= `BOATS_MAX`), `kayak` (the equipped boat, must be owned; client `kayaks.js`), `discovered[]` (`"<petId>:<variant>"`), `pets[]` (`{ uid, id, variant }`, <= `PET_STORAGE_MAX`, unique positive uids; client `petInventory.js` `snapshot()`/`hydrate()`), `petTeam[]` (owned uids, <= `petTeamSize`), `petTeamSize` (1..`PET_TEAM_MAX` 6), `nextPetUid`, `lastSeen`, `daily` (server-written only, see Daily rewards).
- `src/constants.ts` must match the client's `src/config.js` by hand (`WORLD_BOUNDS` incl. the 75 km slide's z and height, `SPAWN`, `SLIDE.run` -> `DISTANCE_MAX`, coach `slots`, pet variants). The client's only link is `src/net.js` (Colyseus SDK); a contract change goes in both projects.
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev). Needs repo var/secret `LEGION_GAME_ID` (= `kayak-and-surf`) and secret `LEGION_DEPLOY_TOKEN`.
